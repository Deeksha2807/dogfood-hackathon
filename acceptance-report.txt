6. NORMALIZATION IMPLEMENTATION-CHOICE STATUS
--------------------------------------------------------------------------------
Status: IMPLEMENTED & DOCUMENTED AS AN ENGINEERING IMPLEMENTATION CHOICE

Specification vs. Implementation Details:
  - Requirement: The hackathon project specification mandated cross-judge score
    normalization to adjust for judge bias.
  - Specification Gap: The official hackathon requirements DID NOT define a
    specific mathematical formula for normalization.
  - Engineering Implementation Choice:
    - Algorithm: Standardized Z-Score normalization mapped to Target Mean 75.0
      and Target Standard Deviation 15.0:
        Z = (Raw - mu_j) / sigma_j
        Norm = clamp(75.0 + 15.0 * Z, 0, 100)
    - Fallback: When sigma_j <= 1e-4 (zero-variance or single evaluation), a
      mean-shift fallback is applied:
        Norm = clamp(Raw - mu_j + 75.0, 0, 100)
    - Integrity: Non-destructive to database raw scores; missing evaluations are
      never padded with zero.
    - Tie Handling: Ties are preserved with identical ranks; secondary sorting
      by submissionId is used strictly for deterministic row ordering and never
      creates an artificial winner. tieBreakerReason explicitly records ties.
  - Documentation Reference: Fully documented in JUDGING.md, ARCHITECTURE.md,
    and DATA-MODEL.md.
